# Использованные паттерны

В проекте используются не только классические GoF-паттерны, но и архитектурные паттерны, которые помогают разделить игровое состояние, правила и интерфейс.

| Паттерн | Где используется | Для чего |
| --- | --- | --- |
| MVC / Model-View-Controller | `include/model`, `include/controller/Controller.h`, `include/view/IView.h`, `libs/view/NcursesView.cpp` | Модель хранит состояние мира и реализует правила, `Controller` переводит пользовательские действия в вызовы сервисов, а `NcursesView` только отображает состояние и читает ввод. Благодаря этому игровая логика не зависит от ncurses и тестируется отдельно |
| Entity-Component / компонентная модель | `include/model/entity/entities/Entity.h`, `include/model/entity/components/*`, `include/model/entity/EntityFactory.h` | Сущность хранит набор компонентов по типу: здоровье, движение, бой, инвентарь, оружие, обзор, ИИ и очки времени. Это позволяет собирать оперативников и врагов из разных возможностей без большой иерархии наследования |
| Factory / статическая фабрика | `include/model/entity/EntityFactory.h` | `EntityFactory` централизованно создает оперативников и типы врагов с нужным набором компонентов и настройками. Код создания не размазан по `main.cpp`, тестам и сервисам |
| Repository | `include/model/repository/Level.h`, `libs/model/repository/Level.cpp` | `Level` является хранилищем уровня: клетки, сущности, позиции сущностей и предметы на карте. Сервисы работают через этот слой, а не напрямую с разрозненными контейнерами |
| Service Layer | `include/model/service/*Service.h`, `libs/model/service/*Service.cpp` | Игровые правила вынесены в сервисы: движение, бой, инвентарь, предметы, обзор, ходы, ИИ и сохранение. Это делает правила переиспользуемыми для контроллера, ИИ, тестов и бенчмарков |
| Observer / Event Bus | `include/model/service/events/EventBus.h`, `libs/model/service/events/EventBus.cpp`, `include/model/service/events/Event.h` | Сервисы публикуют события движения, урона, смерти, использования предметов и разрушения клеток. View подписывается на события и решает, как показать сообщение или анимацию, поэтому обратная связь игроку не смешивается с игровой логикой |
| Interface / полиморфизм | `IView`, `ICell`, `IItemContainer`, `IDestructibleCell`, `Item`, компоненты в `include/model/entity/components` | Общие интерфейсы позволяют обрабатывать разные реализации единообразно: клетки по-разному отвечают на проходимость и прострел, предметы по-разному применяются через `use`, view можно заменить без изменения контроллера |
| Strategy-подобный выбор поведения ИИ | `include/model/entity/components/AIComponent.h`, `include/model/service/AIService.h`, `libs/model/service/AIService.cpp` | У врагов есть профиль поведения `WILD`, `INTELLIGENT` или `FORAGER`. `AIService` оценивает одни и те же возможные действия с разными весами, поэтому агрессивный, стрелковый и собирательный ИИ ведут себя по-разному без отдельного сервиса на каждый тип врага |
| Dependency Injection | `main.cpp`, `include/controller/Controller.h`, `include/model/service/ServiceBase.h` | `main.cpp` создает `World`, сервисы и `EventBus`, а затем передает зависимости в `Controller` и сервисы. Это упрощает тестирование: в unit-тестах можно создать только нужный уровень и нужный сервис |
| Facade / агрегатор состояния мира | `include/model/service/World.h`, `libs/model/service/World.cpp` | `World` собирает текущий `Level`, карты видимости, составы команд и `EventBus` за одним объектом. Контроллеру, view и сервисам не нужно отдельно передавать все эти структуры |
| RAII и владение ресурсами | `std::unique_ptr` в `Entity`, `Level`, `InventoryComponent`, `ItemStorage`; `std::shared_ptr` для `EventBus`; `std::lock_guard` и `std::unique_lock` в `_mt`-версии | Владение сущностями, клетками, компонентами и предметами выражено типами C++. В многопоточной версии блокировки берутся через RAII-объекты, что снижает риск забыть освободить mutex при раннем выходе из функции |
| Singleton | `include/model/service/EntityLock_mt.h` | `EntityLockPool::instance()` возвращает единственный общий пул lock для сущностей. Это нужно, чтобы разные сервисы многопоточной версии синхронизировались через один и тот же набор mutex по `EntityId`, а не создавали независимые lock для одних и тех же сущностей |
| Thread-safe lock pool / упорядоченная синхронизация | `include/model/service/EntityLock_mt.h`, `libs/model/service/*_mt.cpp` | В многопоточной версии `EntityLockPool` выдает lock по `EntityId` и захватывает пару сущностей в стабильном порядке. Это нужно для операций вроде атаки или передачи предметов, где одновременно меняются две сущности и важно избежать deadlock |
| Data Mapper / простая сериализация состояния | `include/model/service/LoadSaveService.h`, `libs/model/service/LoadSaveService.cpp` | `LoadSaveService` преобразует объектную модель мира, клетки, компоненты и предметы в текстовый файл сохранения и обратно. Логика сохранения отделена от классов сущностей и клеток |
