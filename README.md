# Terminal Tactics

[![Terminal Tactics demo](https://asciinema.org/a/eVlApI5d55nfs9fT.svg)](https://asciinema.org/a/eVlApI5d55nfs9fT)

Terminal Tactics - прототип пошаговой тактической игры в терминале на C++23

Проект начинался как учебная работа: нужно было спроектировать объектную модель игры, реализовать игровую логику, интерфейс и покрыть основные части тестами. В итоге получилась небольшая тактическая система с клеточной картой, несколькими типами сущностей, предметами, боем, инвентарем, ИИ и сохранением состояния

Однопоточная версия остается основным вариантом, а многопоточная собирается как отдельный набор целей. Она параллельно обрабатывает ходы ИИ, использует oneTBB и синхронизацию игрового состояния и имеет собственные конкурентные тесты

## Что есть в игре

- Клеточная карта с разными типами клеток: пол, стены, стекло, перегородки, тайники, разрушаемые объекты и контейнеры предметов
- Сущности на базе компонентной модели: оперативники, враги, здоровье, движение, бой, обзор, инвентарь, оружие и очки времени
- Пошаговая система с командами и расходованием очков времени на действия
- Бой: стрельба, ближняя атака, линия огня, урон и перезарядка
- Предметы: оружие, аптечки, подсумки с патронами, подбор, выбрасывание и использование
- ИИ с несколькими профилями поведения: агрессивный, более осторожный и собиратель
- Поле зрения и туман войны
- Отдельная проверяемая многопоточная сборка
- Сохранение и загрузка состояния мира
- Терминальный интерфейс на ncurses
- Unit-тесты на Catch2 для матрицы, клеток, компонентов, сущностей, фабрики, уровня, сервисов и многопоточной синхронизации

## Архитектура

Код разделен на несколько крупных частей:

- `include/model/entity` и `libs/model/entity` - сущности, компоненты и предметы
- `include/model/repository` и `libs/model/repository` - уровень, клетки, позиции сущностей и хранение предметов на карте
- `include/model/service` и `libs/model/service` - игровые правила: движение, бой, инвентарь, предметы, обзор, ИИ, ходы, сохранение
- `include/controller` и `libs/controller` - перевод пользовательских действий в вызовы сервисов
- `include/view` и `libs/view` - ncurses-отображение
- `matrix` - собственный двумерный контейнер
- `tests` - unit-тесты

## Многопоточная версия

Файлы с суффиксом `_mt` - это многопоточная реализация, вынесенная в отдельную сборку. В ней параллелится ход ИИ, используются `std::jthread`, TBB-контейнеры, mutex внутри изменяемых компонентов и `EntityLockPool` для упорядоченной синхронизации операций над сущностями

При включенной MT-сборке CTest запускает отдельную цель `test_mt`: она проверяет конкурентный доступ к уровню и компонентам, порядок блокировок сущностей и параллельное обновление команды. В истории проекта версия также проверялась через ThreadSanitizer без обнаруженных гонок, а сохраненный график показывает прирост производительности более чем в 2 раза на большом числе врагов. Подробности: [docs/threading.md](docs/threading.md)

## Тестирование и качество кода

Основная логика покрыта unit-тестами на Catch2, покрытие ядра проекта и сервисов составляет около 90%. При разработке использовались `clang-tidy`, `cppcheck`, `valgrind` и `ThreadSanitizer`, проект компилировался на GCC и Clang. CI собирает обычную и многопоточную версии, запускает их тесты и отдельно проверяет Docker-сценарий

Подробно о тестах, анализаторах и возможных следующих проверках качества: [docs/quality.md](docs/quality.md)

## Инженерные решения и компромиссы

Ключевые компромиссы проекта: `_mt`-версия собирается отдельно из-за зависимости от oneTBB и стоимости поддержки двух реализаций, компонентная модель реализована без полноценного ECS-фреймворка из-за масштаба проекта, а сохранение сделано текстовым файлом, потому что игра локальная и не требует серверного persistence layer

Подробное объяснение этих решений и план улучшений при росте проекта: [docs/tradeoffs.md](docs/tradeoffs.md)

## Текущий demo-level

Сейчас `main.cpp` создает один демонстрационный уровень прямо в коде. Это пример, на котором можно проверить карту, движение, бой, инвентарь, ИИ, обзор и сохранение состояния

Полноценной фабрики уровней, кампании или системы переключения между несколькими уровнями пока нет. При этом сервис сохранения и загрузки уже реализован: текущее состояние мира можно сохранить на диск и затем восстановить

## Сборка

### Docker

Для полной проверки проекта на чистом окружении нужны только Docker Engine и Docker Compose:

```bash
make docker-test
```

Цель вызывает `docker compose run --build --rm tests`. Команда создает образ на Ubuntu 24.04, устанавливает CMake, GCC, Catch2 3 и oneTBB, собирает обе версии без терминального UI и запускает все CTest-цели. Исходная директория не монтируется, поэтому локальные компиляторы и библиотеки не требуются

### Локальная сборка

Зависимости:

- CMake 3.20+
- компилятор с поддержкой C++23
- ncurses для запуска терминального интерфейса
- Catch2 3 для unit-тестов
- oneTBB только для многопоточной сборки

Обычная сборка:

```bash
make build
```

Запуск тестов:

```bash
make test
```

`BUILD_DIR` и `BUILD_TYPE` можно переопределить, например `make test BUILD_DIR=build-debug BUILD_TYPE=Debug`. Эквивалентные команды CMake по-прежнему можно вызывать напрямую

Запуск всех однопоточных тестов одним исполняемым файлом:

```bash
./build/tests/test_all
```

Запуск игры:

```bash
./build/game_app
```

Если ncurses не найден, CMake соберет библиотеку, тесты и benchmark-и, но пропустит `game_app`

## Многопоточная сборка

```bash
make mt-build
make mt-test
```

Для проверки через ThreadSanitizer доступна цель `make tsan-test`

После этого, при наличии ncurses и TBB, доступны:

```bash
./build-mt/game_app_mt
./build-mt/timing_mt
```

Обычный benchmark:

```bash
./build/timing
```

Benchmark-и пишут результаты в `benchmark.txt`

## Управление

- `WASD` или стрелки - перемещение курсора
- `Enter` - выбрать клетку или подтвердить действие
- `Esc` или Backspace - отмена
- `M` или Tab - переключение режима движения/атаки
- `E` - закончить ход
- `R` - перезарядиться
- `G` - поднять предмет
- `T` - выбросить предмет
- `U` - использовать предмет
- `[` / `]` - переключать предметы на текущей клетке
- `,` / `.` - переключать предметы в инвентаре
- `P` - сохранить игру
- `L` - загрузить игру
- `Q` - выход, нужно нажать два раза для подтверждения

## Как я сейчас позиционирую проект

Это не попытка сделать полноценную игру с готовым балансом и контентом. Сильная часть проекта - модель, сервисы и инженерные решения вокруг них: разделение ответственности, тестируемая игровая логика, сохранение состояния и поддерживаемая многопоточная реализация

Однопоточная версия - основной вариант. Многопоточная версия поддерживается как отдельная opt-in сборка с собственными тестами и CI: она показывает работу с параллелизмом, синхронизацией и TBB, но не включена по умолчанию из-за стоимости поддержки двух реализаций
